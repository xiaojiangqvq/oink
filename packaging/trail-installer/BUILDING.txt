Pointer Trail Enhanced — third-party modification of Oink v0.3.4
Application: 0.3.4-inhouse.110 (build 110); installer revision: 2

Revision 2 retains the exact tested full application MSI and replaces the large
offline WebView2 package with Microsoft's small Evergreen Bootstrapper.
Internet is required only when WebView2 is missing. The standard NSIS Modern UI
wizard and the application features are unchanged. Source archives are separate
release assets; they are not embedded in the installer EXE.

Rebuild the revision 2 wrapper

Use Windows with Python 3.11+, PowerShell, and 7-Zip on PATH. Alternatively,
pass --sevenzip to the build and verifier. The builder downloads the portable
NSIS 3.13 compiler pinned in nsis-toolchain.json, verifies its archive/compiler
hashes and version, and extracts it into --tool-cache without global installation.
Keep tool caches, extracted inputs and generated outputs outside the source tree.
No Rust, Node or application recompilation is needed to repackage this release.

Obtain PointerTrail-Setup.exe and modified-source.zip from the original release:
  https://github.com/xiaojiangqvq/oink/releases/tag/trail-enhanced-0.3.4-1
Extract that EXE with 7-Zip, without running the installer, and locate its
payload/Oink.msi. Use that exact MSI as EXACT_MSI below, and the original
modified-source.zip as APP_SOURCE_ZIP. The bundle builder checks both hashes.
An existing verified output from the original build 110 may also supply the MSI.

Obtain MicrosoftEdgeWebview2Setup.exe from the official Microsoft URL recorded
in webview2-runtime.json. That file also records the resolved download URL,
size, SHA256 and valid Microsoft Authenticode signer. The mutable download link
can later serve another version; use the recorded resolved URL for the pinned
artifact. Packaging refuses an unrecognized binary. Do not run it while building.

Commit all wrapper changes and newly added source files first. Do not modify
the source between preparing the bundle and building/verifying the wrapper.

  python packaging/trail-installer/prepare_bundle.py --msi EXACT_MSI --application-source APP_SOURCE_ZIP --webview2-runtime ..\runtime\MicrosoftEdgeWebview2Setup.exe --output ..\trail-bundle-r2
  python packaging/trail-installer/build.py --bundle ..\trail-bundle-r2 --output ..\trail-installer-r2 --tool-cache ..\nsis-cache
  python packaging/trail-installer/verify_installer.py --installer ..\trail-installer-r2\PointerTrail-Setup.exe --output ..\trail-smoke-r2

Instead of --msi, --package ORIGINAL_MSI_OUTPUT may refer to the retained original
MSI build directory containing its release.json. Do not supply both options.
The direct --msi route needs no separately reconstructed release.json.

For rebuilding from the revised modified-source.zip rather than Git, retain its
sibling source-inventory.json, source-commit.txt and source-changes.patch beside
the extracted pointer-trail-enhanced directory. Run commands inside that source
directory. The bundle builder discovers those metadata files automatically;
--source-inventory and --source-patch can specify their paths explicitly.

Installation behavior and verification limits

The machine-wide wizard offers Overwrite install (default, keeping settings),
Uninstall, and Fresh install (uninstall then reinstall) when Oink is detected.
Uninstall and Fresh install remove local application settings. Without an existing
installation it installs directly. Supported overwrite sources include original
0.3.4 build 108 and the earlier personal patch; newer upstream versions are not
within this release's supported overwrite scope.

The wizard requests administrator rights and uses NSIS's protected temporary
plugin directory. Only when WebView2 is missing does it ask for runtime license
acceptance and run Microsoft's bootstrapper to download and install the runtime.
MSI runs quietly without a second wizard. Logs remain in a protected
C:\ProgramData\Oink-Setup-{GUID} directory (install.log/uninstall.log).
Users open Oink from the Start menu after installation. The elevated installer
does not start the app or set a fresh user's login-start preference. If clean
removal requires a reboot (MSI 3010), reboot before running the installer again.

Old personal-patch backups remain in place. Legacy trail mode migration happens
inside the app on first launch, only if the mode is absent. Existing explicit
choices remain. The official Windows update feed is disabled; future manual
updates are at https://github.com/xiaojiangqvq/oink/releases.

Build and smoke verification extract and inspect the executable without installing
the product, changing cursors or uploading anything. They verify hashes/provenance
and that source archives and the large offline runtime are absent from the EXE.
They do not replace live upgrade or missing-runtime testing. A fresh installation
on a clean Windows computer has not yet been tested; report only checks actually
performed for the release.
